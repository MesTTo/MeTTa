# a31.7 — declare (: perform (-> Atom %Undefined%)) into &metta beside the loader's claim, and have the claim resolve the locator itself with (eval $file)

approach, done, on i26.

## What this has to establish

An equivalence, in both directions. Every library that used to write

    !(import_prolog_functions_from_file (library lib_x.pl) (head ...))

now writes

    (= (package backing) (prolog (library lib_x.pl) (head ...)))

and the two must install the same heads from the same artifacts. One direction
had already been checked when the migration landed and the other had not: that
the new spelling installs what the old one did, but not that it installs it
under the same conditions. The missing direction is where the defect was, and a
counterexample settles it, so the work was to find one and then find what it
refuted.

## The counterexample

    cd extensions/python
    python -m pytest tests/ch19_spaces_backed_by_anything/test_imports.py \
        -q --randomly-seed=424242

The seed is not optional. `pytest-randomly` shuffles, and these tests share one
engine, so two runs of one tree gave `2 failed` and `13 passed`; nothing can be
compared without pinning it.

|---|---|
| pre-migration (`f883970^`) | 13 passed |
| `f883970`, the faces commit | 10 failed, 3 passed |
| `20f5f8b` | 10 failed, 3 passed |
| `1881885`, full migration | 11 failed, 2 passed |

Ten of the failures carried one message:

## Two mechanisms, not one

The first failure in file order is
`test_minimal_lib_install_is_idempotent_after_cross_file_traffic`, and it
poisoned the engine for the rest. Its own refusal named `['unify-mod']`. A
Prolog probe over the same sequence, with `catch_with_backtrace/3` around
`metta_host_load_file/3`, put the frames in order:

    check_prolog_function_names(['Error',...|...], '.../minimal_metta_lib.pl', true)
    import_prolog_functions_from_file('.../minimal_metta_lib.pl', ['Error',...|...], _)
    perform([prolog, '.../minimal_metta_lib.pl'|...], _)

Two things are visible there. The file argument had already been resolved to a
path, so the engine was evaluating inside the row; and the names argument was an
`(Error ...)` term rather than a list, which is what `(unify-mod)` reduces to
once `(: unify-mod (-> Atom Atom Atom Atom %Undefined%))` is in force. Rows
perform after the whole file has loaded, so the declaration always is.

The older spelling never met this. `translate_prolog_import_dl/5` in
`engine/translator/special_forms.pl` is a compile-time special form: it compiles
the file through `translate_expr_dl/4` and passes the name list through
**uncompiled**, which is why a literal list survives. A claim body has a
variable where that literal was, and `translate_expr_dl(Var, G, G, Var)` emits
nothing, so both halves changed at once: the payload started being evaluated by
the caller, and the locator stopped being resolved by the callee.

## The prelude is the wrong home for the mask

An `Atom` mask normally lives in `prelude_declaration/2`, and
`engine/metta/prelude.pl` says so above the table: *has-declared-type,
space-contains and space-admission-verdict each carry an Atom mask ... and this
file is where that mask lives*. A row was added there, with its fixture entry in
`tests/data/prelude-spec.metta` and the count in
`tests/prolog/suites/evaluation/prelude_spec.plt` raised from 47 to 48. The row
loaded:

    register: perform -> [->,'Atom','%Undefined%']
    declaration rows: 48

and the failure was unchanged, at `11 failed, 2 passed`. The reason is
`prelude_declaration_governs_in/2` in `engine/metta/types.pl`:

    prelude_declaration_governs_in(Module, X) :-
        (   metta_self_module(Module)
        ->  true
        ;   \+ fun_in(Module, X)
        ).

The prelude tier is inherited, and an inherited declaration is withheld from a
named module that defines the name itself. `&metta` defines `perform`, because
the loader's claim is its definition, so a prelude row for it governs nowhere.
The mask has to be written into `&metta` alongside the claim, which is where
`metta_loader_source/1` now carries it. The prelude edits were reverted.

## Both halves are load-bearing

Each half removed in turn, on one tree, against
`tests/prolog/suites/seams/packages.plt`:

| removed | tests that fail |
|---|---|
| `(: perform (-> Atom %Undefined%))` | `a_backing_row_reaches_its_claimant_as_data` |
| `(eval $file)` in the claim | `..._installs_the_head_its_artifact_exports`, `..._reaches_its_claimant_as_data`, `..._resolves_its_library_locator`, `a_requirement_loads_before_the_file_that_declares_it` |
| neither | none; 12 of 12 pass |

Without the `eval`, the importer is handed the two-element list
`[library, 'x.pl']` and consults `library` and `x.pl` as separate files:

    source_sink `library' does not exist; source_sink `'_support/collections_data.pl'' does not exist

## The test that discriminates the mask

The field symptom needed state to reproduce. A bare engine loaded
`minimal_metta_lib` cleanly, and importing `lib_reflect` first was enough to
make it refuse, so the suite asserts the contract directly instead. The fixture
names its own head through a nullary equation, which makes the evaluated and
unevaluated readings answer different refusals:

    (= (packages_declared_name) packages_declared_double)
    (= (package backing) (prolog "<artifact>" (packages_declared_name)))

| | refusal |
|---|---|
| row kept as data | `existence_error(procedure, packages_declared_name)` |
| row evaluated | `type_error(list, packages_declared_double)` |

The first names what the file wrote, the second what it reduced to. That is the
contract, stated as an observable that needs no prior engine state.
