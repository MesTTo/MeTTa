# a31.8 — read a load's own package rows from the source-assertion journal through filereader:source_package_row/4 instead of matching the space

approach, done, on i27.

## What this has to establish

A universal: for every load into a space, exactly the rows of the file that
loaded perform, and no others. One counterexample destroys it, and one arrived
without being looked for.

## The counterexample

Adding `a_backing_row_resolves_its_library_locator` to
`tests/prolog/suites/seams/packages.plt` made three later cases fail, each
receiving the error the locator case had already been refused with:

    test packages:a_file_with_no_backing_row_installs_nothing: received error:
      source_sink `.../lib/packages_no_such_library/packages_no_such_library.pl'
      does not exist

The file that case loads is `(= (package version) "0.0.1")`. It declares no
backing at all, so the only way it could raise that is by performing somebody
else's row.

## The mechanism

`metta_perform_package_backings/1` asked the SPACE:

    Backing = ['=', [package, backing], Row],
    Perform = [evalc, [perform, Row], '&metta'],
    forall(eval([match, Space, Backing, Perform], _), true)

`Space`, not the file. The comment directly above `replacing_previous_load/4`
says what was meant, *a file's package rows are performed once the load that
carried them has committed*, and law 14 says the same, *performed at once*. The
predicate did not take the path.

Two consequences, and the second is why the first was never noticed. A row that
refuses is refused again on every later load into that space, forever. And a row
that succeeds is performed again on every later load, so N libraries sharing a
space cost N(N+1)/2 performs where N is right; each re-perform re-consults the
same Prolog file and re-registers the same names, which is idempotent, which is
why it stayed invisible.

## The fix

Ownership is already journalled. `metta_source_load/4` maps a canonical path and
space to the load, and `source_load_assertion(LoadId, stored, Ref)` lists the
atoms that load stored, which is how `withdraw_source_load/3` takes a source's
atoms back out. Reading package rows from it is three goals:

    source_package_row(CanonPath, Space, Kind, Payload) :-
        metta_source_load(CanonPath, Space, LoadId, _),
        source_load_assertion(LoadId, stored, Ref),
        spaces:stored_atom_of_ref(Ref, Space, ['=', [package, Kind], Payload], _).

`source_load_function_names/2` in the same file walks the same journal the same
way, so the idiom is the loader's own. Cost is one indexed lookup plus one
decode per atom this load stored, against the tens of thousands of inferences
the load that just finished spent.

`replacing_previous_load/4` now passes `CanonPath` alongside `Space`, and both
`metta_perform_package_requires/2` and `metta_perform_package_backings/2` read
through the accessor. The nesting `forall(Row, forall(eval(...), true))` keeps
the old behaviour for a row that answers nothing: the original
`forall(eval([match, ...]), true)` succeeded over zero solutions, and
`a_backing_no_claimant_answers_installs_nothing` depends on that.

## What it costs

Twelve files imported one after another into `&self`, reading
`statistics(inferences, _)` around each import, over four fixtures that differ
only in what the file declares. The probe loads `engine/qlf_boot.pl` before
`engine/metta.pl`: a plain `consult` of `metta.pl` takes the `.qlf` beside it
whenever that file's own mtime is older, and the `.qlf` carries the compiled
`interop.pl` from whenever it was built, so two earlier runs of this
measurement compared an edited source against a stale image and answered
backwards.

| what the file declares | loader | cost of import `i`, inferences |
|---|---|---|
| nothing | either | 2,571, flat |
| a row on a token nobody claims | per-file | 11 i + 4,043 |
| a row the loader's claim performs | per-file | 702 i + 6,438 |
| a row the loader's claim performs | whole-space | 2,728 i + 5,087 |

Three things follow, and the third was not what this approach set out to fix.

Reading a file's rows from the journal is flat. The unclaimed-token arm is the
loader's own work with the importer taken out of it, and its 11 inferences per
already-loaded file is the noise floor, not a term.

The whole-space match cost 2,026 inferences per already-loaded file, which is
one re-performed row each. That is the N(N+1)/2 against N stated as a number:
at the twelfth import the older loader performed eleven rows nobody asked it
to, and this approach removes exactly that term.

The remaining 702 per already-loaded file is in the IMPORTER and is untouched
by this change: it is absent when the token is unclaimed and present when
`import_prolog_functions_from_file` runs, so it is the registration checking a
name against a set that grows with every head already registered. Importing N
Prolog-backed libraries into one space is therefore still quadratic overall.
Recorded as i28; not addressed here.

## The check

`a_backing_row_performs_only_for_the_file_that_carries_it` imports a refusing
row, catches its refusal, then imports a file that declares nothing. Widening
`source_package_row/4` back to `metta_source_load(_, Space, LoadId, _)` fails it
along with the two neighbours it used to knock over.
