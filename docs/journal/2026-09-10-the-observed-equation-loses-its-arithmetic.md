### Trace-port deferral

Decided: retain the private syntax table and the shipping loader. Disable the starting thread's `gc` flag immediately after identity dispatch at each exit hook; restore its captured value at every non-exit port and in observation teardown. Consecutive exits keep collection deferred. Enable all ports, including cut and exception, for the observation and restore the caller's visibility mask afterwards. No registration or implementation change in `engine/spaces/receipts.pl` is required, including its pending nearest-transaction walker replacement.

Boundary: inline unification has completed when its debug frame reaches the exit hook. The window includes that hook and the finished listeners. Its excess is the parent's straight-line instructions up to the next port; a collection there requires an instruction's space check, which restarts the instruction, or that port. A collection already pending at the hook's first call port is served before either the owner guard or the flag write. This residual belongs to the host defect and is not removed by choosing a different first goal. The ledger states this window rather than claiming an exact listener interval.

Rejected: a listener-only guard cannot protect the trace hook's own allocations. A native breakpoint probe kept the value because SWI's `callBreakHook` roots the first-write operands and advances its saved PC (`src/pl-wam.c:1330-1412`), but `I_EXITFACT` has no breakpoint flag (`src/pl-vmi.c:2222`), so replacing the tracer would lose fact-entry coverage. A new native GC guard would add a host-specific binary interface where the existing thread-local flag already covers both explicit and implicit collection. Revisit these only if the port window fails an actual supported execution or the host gains complete native coverage for dynamic clauses.

Thread scope: the report covers only its starting thread. `thread_self/1` captures its already-created handle before tracing; the hook's `thread_self(Thread), Thread == Owner` dispatch performs no frame inspection or heap allocation (`src/pl-thread.c:2656-2667,2754-2757`). Only the owner writes its flag. `observe_port/3`, `source_frames/3` and `observation_error/3` inspect native frame attributes, query source-map facts, or update assoc/buffer values; none calls a user goal or creates a thread. The compiler/runtime wrappers execute source under trace, so a source call reaches a restoring call port before thread creation. A regression creates a real child from that path and checks both the inherited flag and the absence of an observation buffer. No process-wide wrapper around thread creation is needed.
