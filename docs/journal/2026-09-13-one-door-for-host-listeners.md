# One door for host listeners
Goal: no registration of a SWI event listener can order an engine mutex before a channel's event-list lock, and the next lock-order cycle of any kind is refused by the gate rather than found as a hang.
Constraint: the engine pays nothing per acquisition in production; no site is exempted by name; a registration is reachable from inside a caller's transaction.

## 2026-09-13: the fourth hang was the same lock
Found: SWI `src/pl-event.c` at `fc7ef84b949378b729052c3ade79c90ce5416abb`: `LOCK_LIST` is a recursive mutex (64-67); `link_event` takes it to register (99-110); `call_event_list` holds it across `PL_call_predicate` for every callback (415-470); `add_event_hook` returns from inside it after a named replacement (145-159, the `swi-named-listener-replacement-lock` entry). So a registration made while holding mutex M orders `M -> event_list(Channel)`, and a callback taking M orders the reverse.
Found: four journal entries are that cycle through four mutexes: 2026-09-06 boot-inference-determinism (a run-time `prolog_listen/3` replacing the handler the collector was inside), 2026-09-07 every-fact-has-a-token (`frame_finished` registered from each worker), 2026-09-08 a-folder-per-concept (the first transactional bound writer blocked on the list lock), and the classes worktree's 2026-09-12 hang (`'$metta_typing_policy'` held by the loader while it registered a `frame_finished` listener, the main thread inside that channel's callback waiting for the policy mutex). Each was repaired at its site; no rule or lane held the class.
Rejected: a door that refuses to register while the calling thread holds any mutex, because plunit holds `plunit` across `run_tests_sync` (`library/ext/plunit/plunit.pl:732`), so every registration a test triggers would be refused. Revisit if the refusal can name only mutexes some callback takes.
Rejected: a static walk from each `with_mutex/2` goal to a registration, because the 2026-09-12 cycle passed through a meta-called goal (`with_typing_policy_stable(spaces:transaction(...))`) that no walk sees. Revisit if `prolog_walk_code/1` follows a goal bound at the call site.
Rejected: a lock-order door around `with_mutex/2` in the engine, because a wrapper adds inferences at each of the 138 acquisition sites and the benches and twins pin inference counts. Revisit if those counts stop being pinned.
Measured: `library(prolog_wrap)` wraps `system:with_mutex/2`, `mutex_lock/1`, `prolog_listen/2,3` and a predicate defined after the wrap; `flag(K, 0, 1)` fails without writing when the flag is 1; inside an engine `thread_self/1` names the owner `mutex_property/2` reports; a compound `flag/3` key collapses to its name and arity; command=`swipl -q -g main -t halt ai-tmp/ai-wrap-and-flag-probe.pl`, `ai-engine-mutex-owner-probe.pl`, `ai-listener-semantics-probe.pl`.
Measured: inside a wrapper body `context_module/1` answers the wrapper's module, a bare predicate channel passed through to the original registers against that module and never fires, and the closure arrives qualified with the caller's context (`m1:cb`); `predicate_indicator` of a frame omits the module for a predicate its context sees unqualified; command=`swipl -q -g main -t halt ai-tmp/ai-ctx-probe.pl`.
Decided: three pieces. `engine/host_listeners.pl` exports `metta_listen/2`, which registers once per process through an atomic `flag/3` claim, qualifies a bare predicate channel with the closure's module, takes no name, offers no removal, and holds no mutex of its own; `tests/prolog/static_checks.pl` refuses any other `prolog_listen/2,3` or `prolog_unlisten/2` under `engine/`, `lib/` and the seats' binding halves; `tests/prolog/lock_order.pl` wraps the mutex and listener primitives in the plunit lane only, records each acquisition order once with the goal it was first taken for, models `event_list(Channel)` as one more mutex held across each callback, and fails the lane on any cycle. Every site converts: the arithmetic-expansion guard, the seam table, the atom-hook watchers, materialization's erase listener (its mutex now guards only the standing engine's creation), the receipt engine's two listeners, the reference watch (one process listener reading each thread's own pending frames, in place of one registration and removal per transaction), and the Python seat's bound watch.

(in transaction)` from `function_free_materialization:overlapping_owned_publications_leave_one_image` and 24 of 25 `references` tests, because materialization and the reference watch register from inside a caller's transaction, where an ordinary assertion is also invisible to other threads and undone by rollback.
