# Fixed-width catalog queries and storage arities
Goal: identify and remove the repeated query cost caused by changing a catalog row's width.
Constraint: keep catalog rows and clause references authoritative, preserve open-tail enumeration, and compare warm QLF images using deterministic inference counts.

Source: SWI-Prolog V10.1.13, commit fc7ef84b949378b729052c3ade79c90ce5416abb, `src/pl-proc.c:1001-1087`, constructs a direct functor lookup only when name and arity are both known. With an unknown arity it enumerates the module procedure table and returns a redo for each matching defined predicate. This is the exact primitive the catalog calls. `engine/spaces/native_matching.pl:get_native_atom/3` already separates proper-list direct lookup from open-tail enumeration.

Rejected: a list membership walk, based on the supplied six-call boot counter and nonsense-name controls; a one-time index build, based on the measured operation slope; a ninth-value JITI threshold, based on the width-six bump and the unchanged native match indexes. The independently changing cache index bucket counts do not account for the measured extra predicate calls.

Decided before implementation: select a predicate directly for proper-list catalog queries, using the existing native storage representation and `clause/3` so references, unification and duplicate order are retained. Enumerate arities only for partial-list queries. This removes the loop over K distinct arities and the SWI walk over P storage-module predicates. Fixed-width selection now costs O(L) for query width L, apart from the selected predicate's clause lookup and answers. The old implementation also allocates a temporary term at every candidate arity, so its allocation volume grows with the sum of those arities, not merely their count. Add regression coverage for width independence, variable heads, duplicate references, open tails and rollback. No new catalog cache or invalidation mechanism is needed.

An ordinary Prolog module can inherit user predicates, so a direct lookup would be unsafe if the storage shared that base. Verified that the actual `$metta_atoms:&metta` storage imports only `system`, matching the private storage contract in `engine/spaces.pl:348`; the engine's reserved storage functor has no system implementation. The new tests also plant a user predicate at an otherwise absent width to verify the boundary.
